# bscan_detection.py

at_tx の B-scan で、次の 3 つが**クラッタの中で見えるか / 見えないか**を判定するツール（Level 6 以降）。

| チャネル | 問い | 観測量 |
|---|---|---|
| 反射 | 反射が見えるか（水氷と決め打ちしない） | ゲート内の包絡ピーク |
| 減衰率 | 地下の減衰率の変化が見えるか | 帯域パワーの時間減衰率 d(dB)/dt |
| 重心周波数のシフトレート | シフトレートの変化が見えるか | df_c/dt |

対象の B-scan（pore_ice / excess_ice など）を、反射体のない基準の B-scan（no_ice）と比べる。`bscan_analysis_requirements.md`（要件案）はこの設計書で置き換える。

---

## 1. 判定の定義

### 1.1 クラッタ基準と検出確率

| 項目 | 定義 |
|---|---|
| クラッタ基準 | 誤報率 **P_FA = 5 %**（`P_FA`） |
| 反射のしきい値 | 基準（no_ice）の全トレースの、同じ時間ゲートの包絡ピークの **95 % 点**（片側）。前後 `REFL_POOL_NS` = 0.5 ns の基準も含めて分布を作る |
| レートのクラッタ範囲 | 基準のブロック間のばらつきの**両側 5 %**（平均 ± 1.96σ。`BAND_METHOD = 'percentile'` で経験分位点） |
| 検出確率 P_D | 対象のトレース（反射）またはブロック（レート）のうち、クラッタ基準の外に出た割合 |
| 判定 | **P_D ≥ 50 %（`PD_VISIBLE`）なら「見える」** |

### 1.2 なぜ「対象 vs 基準の分布」で判定するか

- 実機では、同じ場所の「氷がなかった場合」のデータは得られない。比べられるのは、反射体のない場所でのクラッタの分布だけ。この立場に合わせた。
- 基準と対象は同じランダム場なので、同じ場所どうしの差（paired difference）を取ればクラッタは消える。これは理想的な上限として**参考値だけ**出し、判定には使わない。
- 同じ場なら、氷層より浅い時間では対象と基準が同一になる。そこでの P_D は約 5 % になるはずで、判定の較正チェックになる（run_info に出す）。

### 1.3 減衰率・シフトレートと tanδ の関係

往復走時 t のパワーは P(f, t) ∝ exp(−2π tanδ f t) で減衰する（t は往復走時。片道の距離ではなく時間で書くと、屈折率が消える）。したがって次の関係がある。

```
減衰率     d(10 log10 P_band)/dt = −10 log10(e) · 2π · tanδ · f_c     [dB/ns, f_c は GHz]
シフトレート  df_c/dt              = −2π · tanδ · σ_f²                  [GHz/ns]
```

- 幾何学的な拡がりや散乱強度の深さ変化も減衰率に乗るが、対象と基準で共通なので差には効かない。
- この関係を使って、次の 2 つを Δtanδ に換算して出す。
  - 同じ場所どうしの差（paired_dtand_equiv）
  - クラッタの幅を超えるのに必要な Δtanδ（min_detectable_dtand）

  f_c と σ_f² は窓ごとの基準の値を使う。

## 2. 入力

### 2.1 パス JSON（既存ツールと同じファイルに追加）

```json
{
  "_reference": {
    "excitation_waveform": {
      "dx_00025": { "far_1m": ".../far_1m.out", "at_tx": ".../at_tx_freespace.out" }
    }
  },
  "Level_6": {
    "excitation_waveform": {
      "dx_00025": {
        "pore_ice":   { "bscan": ".../pore/result/Bscan_merged.out" },
        "excess_ice": { "bscan": ".../excess/result/Bscan_merged.out" },
        "no_ice":     { "bscan": ".../no_ice/result/Bscan_merged.out" }
      }
    }
  }
}
```

- 階層を降りていき、「子がすべて {キー: パス}」になった階層を条件の階層とみなす。
- `no_ice`（`REFERENCE_CONDITION`）が基準。それ以外の条件を順に解析する（`TARGET_CONDITIONS` で絞れる）。
- `far_1m` は波源遅延の測定に必須。`at_tx`（自由空間）は直達波の除去に使う（`SUBTRACT_FREESPACE = True` のとき必須）。

### 2.2 記録ファイル

各 B-scan のフォルダ（または 1〜2 つ上）にある `Ascan_level6_record.json` から次を読む。

| 項目 | 用途 |
|---|---|
| 測線 x0 / step | トレースの x 座標 |
| `rho_map_sha256` | 基準と同じランダム場か。違えば警告し、同じ場所どうしの差は意味を持たないと表示する |
| 氷層（有無・描像・深さ・厚さ・氷量）、組成、tx 高さ | 平均媒質の理論（3 章） |
| `surface_y_m`, `dx_m` | 計算領域の底（PML 上端）の走時。これより後は使わない |
| `enable_ice`（基準側） | 基準に氷が入っていたらエラーで止める |

## 3. 平均媒質の理論（印と窓だけに使う）

ランダム性を除いた平均媒質（`THEORY_LEVEL = 'Level_5'`：密度プロファイル＋氷層）を、記録ファイルの値で `subsurface_model` に設定する。そこから次を計算する。

- 地表・氷層上面・氷層下面の往復群走時（波源遅延込み）：図の点線と、減衰率の窓（above / layer / below）の境目
- 氷層中央の tanδ（氷あり / 氷なし）：「理論の変化」の目安
- 計算領域の底の走時

**判定には使わない。** 理論が作れなくても（記録ファイルが無い、`subsurface_model` の版が違うなど）、印なしで解析を続ける。

## 4. 処理

### 4.1 前処理

1. 基準・対象の B-scan を読む（`rxs/rx1/Ez`、[時間, トレース]）。dt と形が一致しなければ止める。
2. 自由空間 at_tx を全トレースから引く（直達波の除去。既存ツールと同じ）。
3. `TRACE_X_RANGE_M` でトレースを選ぶ（既定は全部）。
4. dB の基準は、基準 B-scan の地表反射の包絡ピーク（全トレースの中央値）。

平均トレースを引く背景除去はしない（水平な界面の反射そのものが消えるため）。

### 4.2 反射チャネル

1. 各トレースの包絡（Hilbert）に、半幅 `REFL_GATE_HW_NS` = 1.0 ns のゲートを `REFL_STEP_NS` = 0.05 ns 刻みで滑らせ、ゲート内のピークを取る。
2. 各時刻で、基準の分布の 95 % 点をしきい値にする。
3. 対象のトレースのうち、しきい値を超えた割合が P_D(t)。
4. P_D ≥ 50 % が続く時間帯を「データから見えた反射」として列挙する（理論の界面に近いものには名前を付ける）。
5. 理論の界面の時刻（±ゲート半幅）での P_D と判定も出す。

### 4.3 減衰率・シフトレートのチャネル

1. 各トレースの短時間スペクトル（Tukey 窓、半幅 `SPEC_HW_NS` = 2 ns、`SPEC_STEP_NS` = 0.2 ns 刻み）を作る。
2. 隣り合う `BLOCK_TRACES` = 9 本（0.45 m）ごとにパワーを平均する。**1 ブロックを 1 回の測定とみなす**（位相は使わない。走時の揺らぎで高い周波数が打ち消し合う偏りを避けるため）。
3. 帯域（0.5〜2.0 GHz）のパワー [dB]、重心 f_c、幅 σ_f を時刻ごとに求める。
4. **時間分解のレート**：`RATE_WIN_NS` = 4 ns の移動回帰の傾き。基準のブロックからクラッタ範囲を作り、対象のブロックが外に出た割合を P_D(t) とする。
5. **窓の検定（判定に使う）**：
   - 窓は above（地表〜氷層上面）、layer（氷層）、below（氷層下面〜領域の底）。氷層の無い対象では 1 つの窓。
   - 窓の中から次の時間を除き、残りの時間で直線回帰した傾きをブロックごとに求める。
     - 地表の後ろ `SURFACE_GUARD_NS` = 5 ns
     - 理論の界面の前後
     - **データで見えた反射の前後**
     - 領域の底より後
   - 反射のエネルギーが入るとレートが跳ねるので除く。理論の走時がずれていても外れないよう、データで見えた反射も除く。

level_6/pore/bscan_detection/
├── vs_no_ice/        基準（no_ice）との比較。判定つき（5.1）

### 5.2 対象だけ（`target_only/`）

基準を使わない、対象そのものの姿。判定（P_D、見える / 見えない）は出さない。

- dB は**対象自身の地表反射**（全トレースの中央値）を 0 dB とする。比較の図（基準の地表反射が 0 dB）とは、両者の地表反射の差（通常ほぼ 0）だけずれる。
- 窓（above / layer / below）と灰色の除外帯は比較の図と同じものを使う。両者を並べて見比べられるようにするため。
- ばらつきの帯は対象のブロック間の平均 ± 1.96 σ。これはクラッタの範囲ではなく、対象自身の測定のばらつき。
- 減衰率は見かけの値（幾何拡散・散乱・反射の裾を含む）。tanδ そのものではない。

## 6. 設定（主なもの）

| 変数 | 既定 | 内容 |
|---|---|---|
| `P_FA` | 0.05 | クラッタ基準 |
| `PD_VISIBLE` | 0.5 | 「見える」とする P_D |
| `REFL_GATE_HW_NS` | 1.0 | 反射のゲート半幅 |
| `SPEC_HW_NS` | 2.0 | 短時間スペクトルの窓の半幅（既存 at_tx ツールのゲートと同じ） |
| `BLOCK_TRACES` | 9 | 1 ブロックのトレース数（81 本なら 9 ブロック） |
| `RATE_WIN_NS` | 4.0 | 時間分解のレートの回帰窓 |
| `SURFACE_GUARD_NS` | 5.0 | 地表反射の後ろで除く時間 |
| `TRACE_X_RANGE_M` | None | 端のトレースを除くときに使う |

## 7. 合成データでの動作確認

実データが出る前に、合成の B-scan で動作を確かめた。合成データの条件：

- ガウス型のランダム場（a_x = 0.2 m、a_z = 0.06 m、ε のゆらぎ 5.5 %）、81 本
- 帯域制限パルス（0.5〜2 GHz、波源遅延 5 ns）
- 氷層 1.0〜2.0 m

| 確認項目 | 結果 |
|---|---|
| 波源遅延・地表反射の走時 | 5.000 ns、7.335 ns（理論と一致） |
| 同じ場なので、氷層より浅い時間の P_D は約 5 % になるか | 3.8 % |
| 反射（R = −0.024、pore 相当） | 上面 P_D 79 %、下面 95 % で「見える」。データから見えた時間帯は 2 つで、どちらも界面の位置 |
| 反射（R = −0.00125、excess 相当） | P_D 4〜11 % で「見えない」 |
| 減衰率の差（層内 tanδ を 70 % 下げた合成データ） | 同じ場所どうしの差 +0.068 dB/ns。式の予測 +0.065 dB/ns と一致 |
| 判定（同上） | クラッタの幅は約 1 dB/ns で、差はその 0.06 倍。「見えない」。検出に要る Δtanδ は約 0.05（乾燥レゴリスの tanδ の 10 倍程度） |

**重心周波数のシフトレートは、式の予測より小さく出た**（予測 0.64 MHz/ns に対して 0.27〜0.39 MHz/ns）。原因は次の 2 つ。

- 合成データのクラッタは、ガウス型（a_z = 0.06 m）のため高い周波数のパワーが非常に弱い。帯域の上端では、減衰しない成分（地表反射の裾など）がスペクトルを決めている。
- 速度が変わると、同じ場所どうしでもスペクトルの細かい形がずれる（pore の場合）。

これは実データでも起こりうるので、シフトレートの換算値（Δtanδ）は「減衰する成分だけで帯域が占められている」ときの値として読むこと。

## 8. 既知の限界

| 項目 | 内容 |
|---|---|
| ブロック数が少ない | 81 本 ÷ 9 = 9 ブロック。クラッタ範囲は正規分布の仮定（平均 ± 1.96σ）で作っている。経験分位点（`BAND_METHOD = 'percentile'`）は 9 個では粗い |
| 判定のしきい値 | P_D ≥ 50 % は「半分以上の測定点で見える」という約束。目的に応じて `PD_VISIBLE` を変える |
| 理論の走時 | 平均媒質（Level 5）の値。窓の境目と印だけに使い、判定には使わない |
| 端のトレース | 臨界角の扇形が領域の外に出るトレースも含む。気になるときは `TRACE_X_RANGE_M` で内側だけにして比べる |
| 2 次元 | 拡がり方とクラッタの統計は 2 次元のもの。3 次元の実機に当てはめるときは注意 |
| 同じ場所どうしの差 | 速度の変わる層（pore）では、層より下のクラッタが時間方向にずれるため、差が完全には打ち消し合わない |

- `ascan_spectrum.py` から：`JSON_PATH`、`_select` / `_kind_layer` / `_pick_reference`（JSON の選択）、`load_trace`、`measure_peak`、`save_figure`、`resolve_output_dir`

- 定数のコピーはしない。B-scan の読み込み（2 次元の `rxs/rx1/Ez`）だけは、既存の `load_trace` が 1 列目しか返さないので本ツールに書いた。
